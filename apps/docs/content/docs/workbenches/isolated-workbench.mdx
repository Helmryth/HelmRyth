The isolated workbench gives each operator a containerized Linux desktop on the same machine as Helmryth. It is useful for browser work, downloads, and repeatable automation that should not run directly on your host desktop.

## Requirements

- Docker Desktop, Docker Engine, or a supported Podman setup
- Enough local memory and disk for the desktop image
- A healthy container runtime available to the Helmryth process

On Windows, Podman is the preferred isolated workbench runtime. Helmryth checks Podman before Docker and validates the exact Windows-to-VM workspace mount before reusing a container.

Before starting two desktops on Windows, confirm the Podman machine is running and has enough shared CPU, memory, and disk for both. Podman Desktop exposes that machine under **Settings → Resources**; both Helmryth desktops consume the same machine budget.

## Run two operator workbenches

1. Open **System → Isolated Workbench**, prepare the managed desktop image, and choose **Per operator**.
2. Set **Maximum per-operator desktops** to `2`.
3. Give two operators **Isolated Workbench** as their environment and create each desktop from that operator's Workbench panel.
4. Choose **Open two desktops** from either operator to watch both in one workspace.

Both desktops may keep running, but only one pane can hold interactive control at a time. Switching control releases the previous pane first; opening the two-up workspace never creates or starts a VM.

The equivalent source configuration is:

```json
{
  "localVm": {
    "mode": "per-operator",
    "maxInstances": 2
  }
}
```

Isolated workbenches always run on the same physical host as the Helmryth desktop process. `maxInstances: 2` does not pool one VM from a Mac and another from a Windows PC. To use Windows capacity today, run Helmryth on Windows with its supported Podman lane and create both per-operator desktops there. The BYO-VPS backend is limited to an x86_64 Linux Docker host; do not point it at Windows as a substitute remote isolated workbench. Track cross-host Mac and Windows pooling in your Helmryth issue tracker.

## Persistence

The operator's workspace and browser profile live in a durable mounted directory. Recreating the desktop can repair stale runtime state without deleting the durable workspace.

## Ownership and reuse

Isolated workbench ownership uses a renewable lease. Helmryth validates the resolved image and container safety contract before reuse instead of trusting only a mutable image tag.
