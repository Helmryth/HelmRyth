## Operators and runs

An operator is a durable identity. A run is one workstream with that operator and has its own trace, provider session, gates, costs, and state.

Use separate runs when you want fresh context without duplicating the operator. Messages sent while an operator is busy are queued, and supported providers can be steered while they work.

## Crews

Crews bring several operators into one workstream. Each participant keeps its own process and provider state. Crew timeouts prevent a participant from blocking the whole crew indefinitely.

## Delegation

Operators can hand work to other operators. Delegated runs carry explicit status back into the parent workstream, including completion, failure, and cancellation.

## Rewind and branches

Editing an earlier message creates a new workstream path. Helmryth avoids resuming stale provider sessions after a rewind, so the next run follows the visible branch rather than hidden abandoned state.

## Memory and work folders

Operator memory is visible and editable. An operator may also have a dedicated work folder; crews can use a shared work folder. Cloud workspaces use a stable default so generated files remain discoverable across runs.
