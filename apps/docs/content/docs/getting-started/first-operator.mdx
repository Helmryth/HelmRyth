## Before you start

Install and sign in to at least one supported CLI. Helmryth detects installed engines during onboarding and again from **System settings → Operator engines**.

## Create the operator

1. Select **New or share** in the sidebar.
2. Choose **New operator**.
3. Give the operator a clear name and purpose.
4. Select its operator engine and model.
5. Choose a working folder if it should edit files or work in a repository.

The work folder matters: it becomes the operator's starting context and limits accidental edits elsewhere. Use a dedicated project folder for coding, research, or content work.

## Give it a useful first run

Start with a concrete outcome and the constraints that matter:

```text
Review this project, run the tests, and explain the three highest-impact issues.
Do not change files yet. Link each finding to the relevant file.
```

Once you trust the diagnosis, ask the operator to implement the change. This keeps review and mutation as separate, easy-to-check steps.

## Tune the operator

Open **Operator settings** to change its name, avatar, instructions, engine, model, work folder, and environment setup. Different operators can use different engines and folders at the same time.

<Callout type="warn" title="Authentication belongs to the CLI">
  Helmryth launches the CLIs you installed. If an engine returns a 401 or asks you to sign in, finish that engine's own CLI login, then refresh detection in System settings.
</Callout>
