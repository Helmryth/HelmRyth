# System, settings, engines, and identity QA specification

This document is the executable acceptance contract for Helmryth System, first-run identity setup, the operator dossier, model and engine selection, write-only credentials, Helmryth Mobile settings, the Isolated Workbench settings surface, and the Run ledger. It follows [`TEST-CASE-TEMPLATE.md`](./TEST-CASE-TEMPLATE.md). A release is not accepted by visual inspection alone: every mutation must be checked in the rendered UI, at its transport boundary, after restart, and against the persisted or deliberately non-persisted result.

## Source-of-truth inventory

- UI: `SettingsModal.tsx`, `SettingsPanel.tsx`, `SettingsPrimitives.tsx`, `EnginesSettings.tsx`, `EngineSetup.tsx`, `ModelPicker.tsx`, `ProviderIcons.tsx`, `ApiKeys.tsx`, `NoEngines.tsx`, `CloudBackendPicker.tsx`, `UsageSection.tsx`, `VoiceSettings.tsx`, `TranscriptionSettings.tsx`, `RoomTurnTimeoutSettings.tsx`, `SkinPicker.tsx`, `BotProfileAvatarCard.tsx`, `CompanionSection.tsx`, `PhoneSetupFlow.tsx`, `LocalComputerSection.tsx`, `LocalComputerAutoWarning.tsx`, and `Onboarding.tsx`.
- Renderer state: `src/state/store.tsx`, `src/state/bot-patch-queue.ts`, `src/lib/analytics.ts`, `src/lib/skins.ts`, `src/lib/room-turn-timeout.ts`, `src/lib/usage.ts`, and `src/lib/tts/`.
- Server boundaries: `server/index.ts`, `server/config.ts`, `server/bot-profile.ts`, `server/avatar-image.ts`, `server/local-computer.ts`, and `server/tts/`.
- Native boundaries: `electron/preload.cjs`, `electron/main.mjs`, `electron/diagnostics.mjs`, `electron/updater.mjs`, `electron/updater-coordinator.mjs`, and `electron/skin-overlay.cjs`.
- Product contract: `DESIGN.md`. The accepted visual identity is light-only Helmryth: warm mineral canvas, graphite ink, vermilion command, petrol signal, visible focus, no dark skin, gradients, glass, glow, mascot, or generic chat-product vocabulary.

## Execution fixtures and reset contract

| Fixture | Required state and data |
|---|---|
| `S0 fresh` | Empty isolated `HELMRYTH_DATA_DIR`; no Helmryth local-storage keys; no credential bridges configured; onboarding profile gate absent. Never point this fixture at the user's real `~/.helmryth`. |
| `S1 populated` | Profile `Ada / ada@example.com`; three visible operators; one hidden operator; one crew; settled usage on two operators; one named browser session; one memory topic; no active run. |
| `S2 engines` | One ready authenticated cloud engine, one ready custom/local engine with loaded and unloaded models, one installed but signed-out engine, one missing CLI engine, one unavailable engine with no install descriptor, and one unknown driver shadow. |
| `S3 secrets` | OS credential bridge enabled; Box, OpenCode, ElevenLabs, OpenAI image, AssemblyAI, and Composio credentials configured with synthetic non-production values; `GET /api/config` must expose flags only. |
| `S4 mobile` | Desktop companion bridge enabled; Relay ready; Tailscale and LAN routes available; one paired device with Workbench access off and one with it on. No real account or production Relay tenant. |
| `S5 workbench` | Container-runtime status fixtures for missing runtime, daemon down, image missing, image stale, running/ready shared container, stopped container, unsafe boundary, per-operator mode, capacity reached, and active lease. |
| `S6 failures` | Controllable proxy capable of delay, abort, 400, 404, 409, 413, 415, 500, non-JSON, dropped response after commit, reconnect, and out-of-order completion. |
| `S7 migration` | Legacy skin key set to each of `midnight`, `atelier`, `foundry`, and `lagoon`; inherited analytics opt-out present; old opt-in present without Helmryth opt-in; valid current data alongside intentionally malformed config values. |

Run rendered cases at 390 × 844, 768 × 1024, and 1440 × 900. Run native-only cases in packaged macOS, packaged Windows, and packaged Ubuntu/Xorg builds where the underlying capability is supported. Use browser development shell to prove missing-bridge behavior. Enable reduced motion and 200% zoom for one pass at every rendered surface. For secrets, capture request keys and configured flags, never credential values.

Cleanup after each mutation case: close dialogs; stop or remove disposable test containers; revoke disposable Mobile devices; clear synthetic credentials; delete generated images and browser partitions; restore the fixture snapshot; remove test local-storage keys; and confirm no process still holds the isolated data directory.

## Release gate

- Any P0 failure blocks the release.
- Any P1 failure blocks the affected platform unless a product owner accepts a time-bounded, documented exception with an executable regression case.
- P2 failures require a tracked issue and must not conceal a P0/P1 behavior.
- A control is not complete merely because its click handler fired. It passes only when visible state, persisted/native/API result, restart behavior, failure recovery, accessibility state, privacy boundary, and cleanup all match this contract.
