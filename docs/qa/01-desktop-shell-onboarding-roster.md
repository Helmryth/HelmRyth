# Desktop shell, onboarding, and roster QA plan

This document is the release contract for the Helmryth desktop shell, first-run onboarding, roster navigation, search and command switching, crew creation/import, archive recovery, and update entry points. It is derived from the rendered implementation rather than screenshots or inherited product assumptions.

## Invariants applied to every case

- Run rendered cases at **390×844**, **768×1024**, and **1440×900**. At 390px the roster is a modal-like drawer over the selected workstream; at 768px and 1440px it remains in layout. No control may be clipped, placed off-screen, or require horizontal page scrolling.
- Run every actionable case once by pointer and once by keyboard. Tab order follows visual order; focus has a visible petrol treatment; Enter/Space activates button semantics; Escape cancels only the topmost dismissible surface; focus returns to the opener after close. Context menus must work with right click, `Shift+F10`, and the Context Menu key.
- Confirm accessible name, role, state (`aria-expanded`, `aria-selected`, `aria-checked`, `aria-busy`, disabled), live announcement, and non-color status cue with a screen-reader accessibility snapshot. Decorative marks must remain hidden.
- Repeat motion-producing transitions with `prefers-reduced-motion: reduce`; no spinner or panel transition may be the only status communication. Text contrast must remain at least 4.5:1 and focus/meaningful non-text contrast at least 3:1.
- For every network mutation, retain the request method/path/body, response status/body, resulting SSE frame where applicable, persisted record after reload, and proof that a rejected/delayed/duplicated request does not create a second record or leave an impossible optimistic state.
- Consequential delete/replace actions must not execute from a single accidental pointer or keyboard activation. If the current build lacks the stated confirmation, the case fails; the plan does not redefine unsafe behavior as correct.
- Product telemetry remains silent unless the isolated fixture explicitly opts in and supplies a valid Helmryth-owned HTTPS sink. Profile email, pairing code/token, file contents, workstream IDs, local paths, and error stack traces must never appear in telemetry.

  3. Repeat network, staging, install, and concurrent-check failures.
- **Expected visible output:** Accurate actionable state across both surfaces, clamped progress, safe errors, no stuck restarting state; new version reopens.
- **Expected persisted / network output:** Requests only to configured Helmryth release origin; downloaded artifact hash/signature match published metadata.
- **Failure and recovery assertions:** Background events cannot downgrade download/error; retries single-flight; failed signature/staging never offers install.
- **Accessibility assertions:** Polite status and textual progress; buttons disabled immediately; focus remains available.
- **Security and privacy assertions:** No previous-owner feed or unsigned artifact accepted.
- **Cleanup / reset:** Remove disposable package/profile and retain artifact hashes.
- **Automation mapping:** `update-channel.node-test.mjs`, `updater-coordinator.node-test.mjs`.
- **Evidence to retain:** Release request log, artifact hash/signature, updater state timeline, before/after version screenshot.

## Exit criteria and retained evidence

This domain passes only when every P0/P1 case is `Automated — passing` or has fresh manual evidence on every applicable platform; P2 failures require a filed issue with owner and release decision. The following are explicit blockers, not documentation notes:

- Any one-click operator/crew deletion or roster replacement without consequence-specific confirmation.
- Any stale search/pairing/account response that can overwrite a newer user action.
- Any identity, pairing secret, private address/path, credential, or workstream content in telemetry/logs.
- Any mobile onboarding CTA that is inert with no explanation/retry.
- Any 390px clipped or unreachable critical control, missing keyboard path, invisible focus, or focus escaping a modal.
- Any updater contact with an unowned/implicit feed or unsigned/unverified artifact.

For each run retain: commit SHA and dirty-state diff, OS/architecture/package type, viewport/DPI/reduced-motion, isolated data-directory identifier, fixture seed hash, exact commands, test report, Playwright/trace archive where used, redacted HAR/IPC log, accessibility snapshots, screenshots for first/empty/loading/error/success states, persisted-record diff after reload, and issue links for every failed expectation. Never retain live pairing codes, QR payloads, tokens, credentials, private file contents, or human profile email.
