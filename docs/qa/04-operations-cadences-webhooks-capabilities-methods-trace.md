# Operations, cadences, webhooks, capabilities, methods, and Trace QA

This document is the executable QA contract for Helmryth's Operations surfaces. It covers the rendered Operations map, section context, Runs & cadences calendar, webhook receiver, Capabilities catalog and in-workstream connection cards, crew package import/export, method capture and method packages, Trace, folded activity runs, and cadence receipts. It also covers the local APIs, persistence, live events, and public package deep link that make those controls truthful.

## Scope, source, and route inventory

| Surface | Entry point | Owned controls and backing boundaries |
|---|---|---|
| Operations map | Score rail **Operations map**; `activeView="team-map"` | `TeamMapPage`, `GET /api/team-map`, `GET/PUT /api/section-context?section=`, operator and handoff navigation |
| Runs & cadences | Score rail **Runs & cadences**; `activeView="routines"`, **Cadences** tab | `RoutinesPage`, `RoutineRunCard`, `GET/POST /api/routines`, `PATCH/DELETE /api/routines/:id`, `POST /api/routines/:id/run`, `POST /api/routine-runs/:id/{cancel,seen}` |
| Webhooks | **Runs & cadences** > **Webhooks** | `WebhooksPanel`, management API `/api/webhooks`, isolated receiver `GET /health` and `POST /hooks/:endpointId[/:secret]` |
| Capabilities | Score rail **Capabilities** modal | `PluginsPanel`, catalog/status/authorize/disconnect routes under `/api/connectors`, cached non-secret inventory, external OAuth handoff |
| In-workstream connection request | Connector message card | `ConnectorCard`, `/api/bots/:botId/connector-cards/:messageId/{authorize,status,resume,dismiss}` |
| Crew library and packages | Roster add menu > **Crew library**, **Export roster**, or `helmryth://install?url=` | `TeamLibraryPanel`, `POST /api/teams/export`, `/api/team-library/*`, `GET /api/teams/scout`, `GET /api/teams/scout/directory`, `GET /api/teams/imports`, `POST /api/teams/import`, `POST /api/teams/imports/:transactionId/undo`, Electron package-link allowlist |
| Method capture | Score rail **Record a method** when enabled | `SkillRecorderPage`, desktop recorder IPC, screen/microphone/transcription boundaries, local `skills/<id>` package output |
| Imported methods | `/api/bots/:botId/skills` | GitHub import, review, disabled-by-default enablement, read/remove endpoints, prompt selection boundary |
| Trace | Workstream header **Trace** button; `inspectorOpen` | `InspectorPanel`, `GET /api/threads/:threadId/events?limit=`, `/api/events` replay/live stream, runtime/native log projection |
| Activity and run receipts | Workstream transcript and cadence calendar | `ActivityRun`, `RoutineRunCard`, task navigation, gate navigation, durable run lifecycle and redaction |

There are no browser path routes for these application views: view selection is reducer state. A test must therefore enter through the visible score rail or workstream control, then assert reducer-selected content and modal mutual exclusion. The only public deep link in this scope is the reviewed package installer described in `OPS-PKG-014` through `OPS-PKG-018`.

## Required environments and fixtures

Run all deterministic unit and server cases against a temporary `HELMRYTH_DATA_DIR`; never point destructive or import tests at a real `~/.helmryth` profile. Use these named fixtures so results are comparable:

- `empty`: configured app server, zero visible operators, zero crews, zero cadences, zero webhooks, empty logs.
- `operations`: visible operators Rivet, Cairn, and Vesper; one archived operator; General and Product sections; one lead operator; one direct-message collaboration; one queued and one running delegation.
- `cadences`: local daily weekday cadence, hosted one-time cadence, paused daily cadence, deleted-operator receipt, and receipts in queued, running, waiting, completed, failed, cancelled, and missed states.
- `webhooks`: enabled local webhook, paused webhook, pending-verification webhook, event allowlist `push, workflow_run`, and an isolated receiver bound to `127.0.0.1` on an ephemeral port.
- `capabilities`: catalog with OAuth, no-auth, connected single-account, connected multi-account, pending, expired, and unknown services; an unreadable credential-store response; popup-blocked browser and desktop external-open variants.
- `method-capture`: macOS desktop bridge fixture; granted, denied, and revoked Screen Recording, Microphone, Accessibility, and Input Monitoring states; AssemblyAI ready/unavailable/stream-failure fixtures; 601 native events; visible secure-field and clipboard sentinel strings.
- `trace`: one known task thread and one crew thread with runtime/native NDJSON, corrupt lines, multibyte content, over-limit history, replay cursor gap, and events that arrive during a disk refresh.
- `package`: valid `helmryth.package` JSON, portable Markdown, supported legacy JSON, duplicate operator keys, dangling references, 201 operators, oversized file, public GitHub repository/blob/raw URLs, and untrusted host/protocol/credential URLs.

For browser execution, capture at 390x844, 768x1024, and 1440x1000 in the light Helmryth skin. Repeat consequential keyboard paths with mouse disconnected, `prefers-reduced-motion: reduce`, 200% zoom, and a screen reader. Each evidence bundle must retain the viewport screenshot, accessibility snapshot, console/network errors, API response, and the relevant temporary persistence file after secrets are redacted.

### 3. Execute rendered control sweeps

For each rendered view, use the following order and retain one trace per layout rather than screenshots alone:

1. Enter from the visible score rail/workstream control, then verify heading, selected state, focus entry, and mutually exclusive panels.
2. Exercise first use, loading, populated, partial, stale, offline, recoverable error, terminal error, and retry.
3. Activate every button/menu/tab/select/input/details row once with mouse and once with keyboard; test cancellation/Escape/backdrop and focus return.
4. Repeat destructive actions with cancel, confirm, double activation, delayed response, server error, and restart at the persistence boundary.
5. Run at 390x844, 768x1024, and 1440x1000, then 200% zoom and reduced motion.
6. Capture accessibility tree names/states, focus order, live announcements, and color-independent status meaning.
7. For network actions, retain request/response status and body with secrets removed, emitted SSE sequence, resulting UI, and persisted file diff.

### 4. Execute resilience and concurrency sweeps

- Delay response A, issue mutation/request B, resolve B before A, and prove generation ownership for map, catalog, account, package, Trace, and task-switch flows.
- Drop receiver, app server, SSE, Conduit, OAuth popup, AssemblyAI, native recorder, and filesystem access independently; verify accurate stale/error/retry states.

- Submit duplicate cadence, webhook, import, account, and method actions from two clients/windows.
- Rotate/delete capability and webhook credentials externally while the relevant modal is mounted and while it is closed.
- Run shared-cwd checkpoint restore and simultaneous crew replace imports to exercise cross-owner locks.

### 5. Clean up and retain evidence

1. Stop capture streams, helper processes, OAuth polling, webhook receiver, EventSource clients, and app/server processes.
2. Revoke test provider accounts and invalidate webhook/private URLs created during the run.
3. Archive only sanitized screenshots, accessibility snapshots, traces, response bodies, event sequences, file-mode listings, and hashes.

5. Record every case as Pass, Fail, Blocked external prerequisite, or Not applicable with platform and evidence link. A skipped case without a written prerequisite is a failure.

## Release acceptance gate

The Operations area is release-ready only when all of the following are true:

- Every P0 case passes on each applicable platform; every P1 passes or has an owner-approved, time-bounded release waiver with user impact.
- All `OPS-BLOCK-*` rows in this inventory are fixed and retained as mandatory regression cases; none count as active blockers.
- No control lacks a unique accessible name, state, visible focus, disabled reason, or safe narrow-screen layout.
- No stale/unknown state enables authorization, revocation, deletion, restore, package activation, or secret rotation.
- Every destructive action has cancel/confirm, retry, duplicate-action, partial-failure, restart, and cleanup evidence.
- Credentials, webhook payloads, prompts, outputs, event raw fields, and account metadata satisfy both in-flight redaction and owner-only at-rest permissions.
- Cadence/webhook/package operations are idempotent or explicitly model each intentional repeat as a new operation.
- Public package links, remote GitHub fetches, webhook ingress, and Conduit authorization remain allowlisted and fail closed.
- Repository-wide tests, typecheck, production build, brand-residue check, and contrast check pass on the exact release tree.
